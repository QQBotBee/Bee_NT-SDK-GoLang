# BeeNT Go 设置窗口开发规范

## 当前实现

设置窗口位于 Go 工作进程，不进入 C 壳 DLL。实现都在 `settings.go`：

- 布局常量、DPI 缩放和设置模型：`settingsLayout`、`settingsModel`、`defaultSettingsModel()`。
- Win32 窗口实现：`showSettingsWindow()`、`closeSettingsWindow()`、窗口线程与窗口过程。
- 宿主进程监控：`startHostWatcher()`。

非 Windows 平台由 `settings_other.go` 提供空实现，只用来让 `go vet` 和单元测试能在其他系统上编译。

## 行为约定

- 默认客户区 640×420，按系统 DPI 等比缩放。
- 固定尺寸窗口：标题栏、系统菜单、最小化按钮；不使用可调整大小的边框，也没有最大化按钮。
- 置顶显示，首次打开居中。
- 重复点击设置只恢复并聚焦已有窗口，不创建第二个窗口。
- 标题和说明文字改 `defaultSettingsModel()` 即可。

## 生命周期注意事项

不要在 `DllMain` 或 C 壳里创建设置窗口。窗口只能由工作进程收到 `settings` 事件时打开（`onSettings` 调用 `showSettingsWindow()`）。窗口线程用 `runtime.LockOSThread` 固定，退出后工作进程才允许结束。

禁用、卸载和 `stop` 事件的清理顺序：

```text
置 closing 标志
→ PostMessage(WM_CLOSE)
→ 窗口线程 DestroyWindow / PostQuitMessage
→ 等待消息循环退出
→ 工作进程继续停止
```

`closeSettingsWindow()` 会阻塞到窗口线程真正退出，调用它时不要持有窗口线程可能等待的锁。

## 真实 Windows 验收清单

`go test` 只能验证布局计算等纯逻辑，以下项目必须在 Bee×NT 中人工确认：

- [ ] 设置菜单能打开窗口
- [ ] 窗口居中并置顶
- [ ] 重复点击只存在一个窗口并聚焦
- [ ] 标题、说明文字可见，中文显示正常
- [ ] 标题栏可拖动
- [ ] 四边四角不能缩放
- [ ] 最小化、关闭正常
- [ ] 禁用、卸载后窗口消失
- [ ] 卸载后工作进程退出
- [ ] 重新加载插件后仍可再次打开设置窗口
- [ ] 高 DPI 下无裁切或重叠

编译成功不等于界面验收成功。
