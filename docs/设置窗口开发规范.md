# BeeNT Go 设置窗口开发规范

设置窗口运行在独立Go Worker中。业务入口为 `plugin_main.go` 的 `onSettings()`，当前调用 `showSettingsWindow()`；窗口模型、Win32消息循环及GDI/GDI+绘制均在 [settings.go](../settings.go)，非Windows测试桩在 [settings_nonwindows.go](../settings_nonwindows.go)。本仓库没有单独的 `settings_window_windows.go`，改界面前应读真实文件。

## 可直接复制的设置开发提示词

```text

配置字段：[名称、类型、默认值、范围、是否敏感]
交互：[控件排列、保存/取消/恢复默认、错误提示、保存后生效方式]
数据文件：[文件名、是否兼容旧配置]

先读取AGENTS.md、docs/AI开发指南.md、docs/设置窗口开发规范.md、
plugin_main.go、settings.go、settings_nonwindows.go、
worker_runtime.go、docs/验证记录.md；使用API前再读API参考和具体方法源码。

仅修改设置窗口、业务配置及相应测试，不改C壳、IPC、导出和构建工具链。
保留onSettings -> showSettingsWindow入口，未启用时也能打开。
```

## 修改点与当前能力

| 位置 | 当前职责 | 常见修改 |
| --- | --- | --- |
| `settingsModel` / `defaultSettingsModel()` | 标题、说明、状态三项文本 | 文案、配置快照与状态显示 |
| `settingsBaseWidth/Height/Padding/TitleHeight` | 96 DPI下的640×420、24边距、48标题区 | 统一布局尺寸 |
| `defaultSettingsLayout(dpi)` / `scaleDPI` | 尺寸缩放、固定窗口约束 | 新控件与绘制坐标都走同一缩放 |
| `showSettingsWindow()` | 单实例、恢复最小化、置顶和聚焦 | 保留生命周期语义 |
| `settingsWindowThread(done)` | 锁定OS线程、注册类、创建窗口、消息循环、退出清理 | 在窗口线程创建和释放控件 |
| `settingsWindowProc()` | 绘制、尺寸限制、关闭与销毁消息 | 控件消息、校验触发、异步结果通知 |
| `paintSettings()` / `drawWindowText()` | 图形、Unicode文字、字体与画刷释放 | 配置布局及显示 |
| `closeSettingsWindow()` | 标记closing、发WM_CLOSE、等待done | 保留等待窗口真正退出 |

当前是说明/状态展示模板，没有输入框、保存按钮或配置文件实现。需要交互时，应补齐控件ID、消息路由、值读取、校验、持久化与业务生效流程；不能仅改绘制文案就宣称配置已经保存。`defaultSettingsModel().Status` 当前为固定文本“插件运行正常”，不等于实时启用状态。

纯文案需求可替换同名函数，保留其它函数不变：

```go
func defaultSettingsModel() settingsModel {
    return settingsModel{
        Title:       PluginName + " 设置",
        Description: "在这里配置插件功能。修改配置后，请点击保存。",
        Status:      "请检查并保存配置",
    }
}
```

此示例只改变文案，不提供保存按钮；实际做保存界面时再实现相应控件。不要把 `showSettingsWindow()` 替换为一个阻塞对话框并在 `onSettings` 内一直等待关闭，事件回调应及时返回。

## 单实例与关闭协议

单实例状态在 `settingsNative`：`hwnd`为已创建窗口，`done`表示窗口线程存在，`closing`表示需要关闭。它们必须受同一把锁保护，不能只判断 `hwnd != 0`；窗口线程刚启动时HWND尚未创建，`done != nil`已经必须阻止第二次创建。

正常打开：

```text
onSettings
→ showSettingsWindow
→ 锁内设置done，启动窗口goroutine
→ runtime.LockOSThread
→ 注册窗口类、创建HWND、发布到settingsNative
→ ShowWindow、置顶/聚焦、进入消息循环
```

重复点击设置时复用已有HWND；最小化后先 `SW_RESTORE`，再 `SetWindowPos` 和 `SetForegroundWindow`。创建或关闭过程中收到重复打开请求可以直接返回，不能再创建第二个窗口线程。用户主动关闭后，消息循环退出，清理状态并关闭done，之后才能重新打开。

禁用/卸载关闭：

```text
onDisable：取消业务任务并等待
→ closeSettingsWindow：锁内置closing，取出hwnd和done后解锁
→ 已有HWND时PostMessage(WM_CLOSE)
→ 窗口线程DestroyWindow
→ WM_DESTROY：PostQuitMessage
→ GetMessage退出，清理窗口类/状态，close(done)
→ closeSettingsWindow返回
→ 生命周期回调返回，原生壳停止Worker
```

如果关闭发生在HWND创建之前，窗口线程创建后会检查closing，立即销毁，不再展示窗口。不要删掉这个分支，也不要在窗口尚未出现时直接把done置空。当前 [settings_test.go](../settings_test.go) 的 `TestSettingsCloseBeforeWindowCreated` 覆盖这条路径。

`closeSettingsWindow()`需要等待线程退出，不能在窗口线程/窗口过程内部调用它，否则会等待自身。用户点关闭时走 `WM_CLOSE` → `DestroyWindow`，不要从任意Go后台线程直接销毁HWND。清理等待期间不能持有 `settingsNative` 或配置锁；窗口线程也需要它们才能退出。

`onUnload()`当前会复用 `onDisable()`，清理要可重复调用。BeeNT重载可以只调用禁用后释放DLL，因此窗口和任务清理不能只放卸载回调。Worker的stop/正常退出路径还会关闭窗口；宿主PID消失时的进程退出是兜底，不能依赖它代替正常保存和清理。

## 布局、DPI与Unicode

- 默认客户区640×420、边距24、标题区48，单位是96 DPI下的逻辑像素，实际使用 `scaleDPI`。外框通过 `AdjustWindowRectEx` 计算，不把客户区尺寸当成包含标题栏的总尺寸。
- 固定窗口样式为 `WS_OVERLAPPED | WS_CAPTION | WS_SYSMENU | WS_MINIMIZEBOX`，没有 `WS_THICKFRAME`、`WS_SIZEBOX` 或最大化按钮。`WM_GETMINMAXINFO`进一步约束跟踪尺寸。
- 当前使用主屏尺寸首次居中，负坐标截为0；默认 `WS_EX_TOPMOST`，重复打开恢复置顶。不要声称已实现多显示器工作区居中或每显示器动态DPI，当前代码读取的是屏幕DC的系统DPI。
- 所有文本走Unicode宽字符API，如 `CreateWindowExW`、`DrawTextW`、`syscall.UTF16PtrFromString`；字体为 `Microsoft YaHei UI`。用户输入含NUL时转换会失败，新增输入处理需返回明确校验错误。
- 文字使用标题22、正文14的缩放字号。长说明用 `DT_WORDBREAK`，标题/状态单行；新增长字段需要检查文字溢出，不靠缩小所有文字掩盖布局问题。
- 保持x86 Win32结构布局；不得把指针字段改成 `int32`，不要混用非Windows测试桩声称实际窗口可用。

## 绘制和原生资源

每轮 `WM_PAINT` 由 `BeginPaint/EndPaint`配对。当前先用GDI填充底色，再用GDI+绘制卡片、强调条和状态圆点，删除GDI+画刷/graphics并关闭GDI+，最后用GDI的 `DrawTextW`统一绘制文字。保持这个顺序，避免后绘制图形覆盖文字。

新增画刷、字体、位图、DC、GDI+对象都要规定创建与释放位置。选入HDC的对象先恢复原对象再删除；不要在每次重绘后泄漏句柄，也不要删除仍被HDC选中的字体。沿用 `drawWindowText` 的恢复顺序。不要在 `WM_PAINT` 内进行磁盘读取、HTTP、SDK调用、等待goroutine或修改持久状态，绘制应使用内存快照。

窗口过程和业务回调不在同一线程：窗口线程负责Win32对象，Worker事件负责业务生命周期，后台任务可能同时访问配置。新增跨线程更新时，将结果存入受保护状态并发自定义窗口消息，由窗口线程更新控件或请求重绘；不要在后台线程直接读写控件句柄和控件内容。自定义消息需选取无冲突值并明确参数所有权，不能传已失效的Go临时指针。

## 配置与后台操作

配置文件使用UTF-8和 `filepath.Join(dataDir, "config.json")`，其中 `dataDir, err := GetAppDataDir()`。目录为 `<BeeNT宿主EXE目录>\plugin_data\<PluginName>`，Worker进程可能被释放到这里，但文件名与PID会变化；不要依据临时exe名创建第二套目录。框架卸载插件可能删除整个数据目录，需持久保留的数据另行备份。

推荐配置流程为“读取到草稿 → 编辑 → 校验 → 写入 → 发布新快照 → 提示成功”。保存失败保留草稿并显示原因，不写成功状态。新增文件写入需考虑临时文件、替换失败与并发保存；不要忽略Windows重命名失败，也不要让半份JSON覆盖上一份可用配置。字段应有默认值，旧配置缺字段时明确采用默认值，校验失败不能自动执行管理类API。

未启用时也能打开设置，所以读取/编辑/保存配置不能依赖 `pluginTasks.ctx` 已存在。仅在启用期间执行的任务仍应由 `onEnable`启动。窗口自身的网络校验或预览另建可取消任务，关窗时取消并等待，不能加入一个只有禁用才取消的任务后让关窗等待它。设置任务与启用任务的清理顺序要明确，避免相互等待。

SDK允许窗口和后台任务调用 `NewBeeNTAPI()`，但调用可能阻塞，不能直接放在窗口过程或绘制函数里。用后台任务处理，结果再交回窗口线程；锁只保护短时间状态读写。SDK没有 `CallContext`，200秒超时不等于取消了框架执行；慢操作应防止重复提交，不能承诺点击关闭即可中断已经发出的SDK调用。后台任务登记、context取消与WaitGroup等待模式见 [AI开发指南](AI开发指南.md) 的“后台任务：登记、取消、等待”。

宿主边界为GBK，Go配置与窗口文本为UTF-8/UTF-16；窗口显示不需要GBK转换。发送中文/emoji通过SDK即可。日志写 `os.Stderr` 或数据目录，原始stdout属于IPC；Worker已将Go的stdout重定向到stderr，也不应绕过它写原始标准输出句柄。

## 构建与可复跑检查

保持Go1.20源码兼容。正式插件统一通过 `build.bat` 使用精确Go1.20.14构建，兼容Server2012R2；按需指定输出名称：

```bat
build.bat
build.bat MyPlugin.dll
```

日常双击根目录 `build.bat`或在CMD使用上面的命令编译当前业务，再将生成的DLL导入真实BeeNT框架检查界面与业务功能；自动化可选加 `--no-pause`。版本、PE、哈希及导入表由构建内部检查，`build/`只输出插件DLL。内部构建实现位于 `other/build.ps1`，供构建维护使用，不是额外的日常入口；其中的 `-GoExecutable` 路径必须指向实际Go1.20.14，不能用于切换版本。

普通业务开发者按下一节清单在真实BeeNT中检查窗口即可，无需阅读内部测试源码。维护窗口实现时，可在交互桌面上显式运行真实窗口单测（以下 `go`应是本次要求的精确工具链）：

```powershell
$env:BEENT_SETTINGS_UI_TEST = '1'
try {
    go test -count=1 -run '^TestSettings' .
    if ($LASTEXITCODE -ne 0) { throw '设置窗口测试失败' }
} finally {
    Remove-Item Env:BEENT_SETTINGS_UI_TEST -ErrorAction SilentlyContinue
}
```

还应在386目标执行窗口单测并跑常规测试/vet；并发变化在工具链和宿主支持时运行race，如实记录当前检测器启动限制。非Windows `settings_nonwindows.go`为空实现，不能验证HWND、消息循环或Unicode绘制。最终DLL还要通过原生模拟宿主调用真实初始化JSON里的setting地址；替换下面路径及预期插件名：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File other\tests\run-settings-host.ps1 -DllPath 'build\MyPlugin.dll' -ExpectedPluginName '我的插件'
```

该测试检查未启用直接打开、可见HWND、重复设置复用、关闭、重开和禁用销毁。它不会判断所有控件文案、保存行为或高DPI排版。窗口打不开时先看数据目录的 `bridge.log` 与 `worker-stderr.log`：Worker没有启动也会导致设置无反应，不能直接判断为绘制问题。相关诊断用例见 [run-diagnostic-host.ps1](../other/tests/run-diagnostic-host.ps1)。

## 实机回归清单与已知范围

2026-11-05，用户确认此前实测的SDK1.0.1在真实BeeNT / Server2012R2的16项验收全部通过；记录见 [历史验收](history/BeeNT实机验收.md) 与 [验证记录](验证记录.md)。后续业务或界面改动仍需回归对应行为。

- [ ] 未启用直接打开设置，不自动启动启用期间任务。
- [ ] 多次/快速点击只存在一个窗口，最小化后可恢复聚焦。
- [ ] 首次居中、标题可拖动、不能缩放/最大化，最小化和关闭正常。
- [ ] 中文、emoji、长文本及100%/125%/150%等系统DPI无明显裁切、覆盖或乱码。
- [ ] 输入边界、保存成功/失败、取消、恢复默认和重开读取符合本次业务约定。
- [ ] 窗口可见时禁用、刚打开立即禁用，都能关闭并结束窗口线程。
- [ ] 关闭后重开、禁用后重新启用、重载至少多轮，无残留窗口/Worker或持续增加的GDI句柄。
- [ ] 正常卸载/退出时任务和窗口结束，已承诺保存的数据完整。

这些项目中新增控件、动态配置、完整DPI组合与长时间资源稳定性，需要本次改动自己的证据；既有16项通过不能自动覆盖后续界面功能，也不代表全部97个API真实联网行为均验证。
