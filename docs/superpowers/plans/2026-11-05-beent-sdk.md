# BeeNT SDK Implementation Plan

**Goal:** 交付可构建的 BeeNT Go 插件开发模板及单 DLL。

**Architecture:** 原生 C 壳处理 BeeNT ABI，资源内嵌 Go Worker 处理业务，双向 JSON Lines IPC 转发框架 API。

**Tech Stack:** Go 1.20.14（当前统一工具链）、Windows/386、Zig C、CP936、golang.org/x/text v0.22.0。

**Spec:** ../specs/2026-11-05-beent-sdk-design.md

## Global Constraints

- Go Runtime 仅存在于 Worker，宿主 DLL 无 cgo。
- API 操作码 1–97，索引 int32，ID 为字符串，时间戳 int64。
- APITransport.Call([]byte) ([]byte,error) 传 UTF-8 命令，C 转换 GBK。
- stdout 只输出 IPC，唯一读取循环按 ID 分发结果。
- 不修改 BeeSDK-GoLang 和参考文件，不提交或推送。

## Review Focus

- 框架重载只触发 disable，不能遗留未保护的 DLL 线程。
- API 消息乱序、后台任务和设置回调不能抢读或永久挂住宿主。
- GBK 不可表示字符保留 Unicode 转义，不静默损坏文字。
- 异常列表、空结果和分隔符出现在业务内容时明确返回错误。
- 元数据不得破坏 JSON 或让数据目录逃逸。

## Tasks

- [x] 1. SDK：先编写协议及结果解析回归测试，确认缺失功能失败；实现 1–97 封装、类型、事件及 API 文档。
- [x] 2. C 壳与构建：实现初始化与回调 ABI、Worker 管理、后台 API 泵、元数据生成及一键构建；运行元数据测试和模拟宿主。
- [x] 3. Worker：先编写并发、EOF、超时和事件测试；实现唯一读循环、请求分发、panic 隔离、生命周期和插件业务示例；复用设置窗口。
- [x] 4. 验证交付：amd64/386 go test 与 go vet、Windows/386 DLL 构建、模拟宿主加载和重载全部通过；独立代码审阅发现的问题已修复；race 已尝试但本机 ThreadSanitizer 启动失败，未获通过结论；详见 ../../验证记录.md。

## 审阅与修复记录

- 386 原子计数器未对齐崩溃：先运行386测试复现panic，改用 atomic.Uint64 后通过完整386测试。
- 设置窗口创建期间关闭丢失：386原生回归测试先失败，发布 HWND 时检查 closing 并销毁，修复后通过；同时修正 amd64 WNDCLASSEX 和 PAINTSTRUCT 布局并加入实际尺寸断言。
- API 同步写阻塞不受超时控制：阻塞 writer 测试先失败，改用一个固定容量写队列，调用等待受超时/断连控制，回归测试通过。
- Windows 同一同步双向句柄导致真实 Go Worker 读写死锁：最终 Worker 模拟宿主暴露问题后，改为两条独立单向管道，三轮最终 DLL 生命周期测试通过。
- 并发回调期间 disable/uninstall：增加停止入口、取消/排空等待调用和模块 guard，原生并发禁用/卸载后立即 FreeLibrary 测试通过。正常宿主必须在生命周期返回前持有 DLL 原始引用，之后停止投递旧回调。
